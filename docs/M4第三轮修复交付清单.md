## 2. B5：路径身份统一为唯一 POSIX 相对路径

**问题复述**：`resolve_safe_path()` 只回绝对 `Path`，DB 却以相对串为身份。`cfo\a.md` 与 `cfo/a.md` 解析到同一文件、却是两个 `stored_path`：反斜杠导入后正斜杠删除会删掉盘上文件、查不到文档行，chunks 与文档行残留，删除代次墓碑也分裂成两条（B4 保护因此可被路径别名绕过）。

**实现**：`opc_workbench/vault.py` 新增唯一入口

```
normalize_relpath(rel) -> str
```
- 反斜杠 → `/`；丢弃空段与 `.` 段（`./cfo//a.md` → `cfo/a.md`）；
- 拒绝：空串、NUL、驱动器 / UNC 前缀（`ntpath.splitdrive`）、任何 `:`（NTFS ADS）、前导 `/`、任一 `..` 段；
- `resolve_safe_path()` 内部改为「先 `normalize_relpath` → 拼根 → `resolve()` 复核逃逸」，校验仍发生在任何文件读取之前，语义与拒绝集合不变。

**调用点（同一入口，不再各自造串）**：`ingest`、`write_doc`（意图表键/落盘/索引同一串）、`delete`、`_replay_deletion`（墓碑与行同键）、`mark_missing`、`purge_missing`（历史行读取时兜底归一）、`recover`（`pending_vault_writes` 重放）、`snapshot`（watcher 扫描键）。

**回归**（`tests/test_knowledge_path_identity.py`，23 条）：

| 用例 | 断言落点 |
|---|---|
| `test_backslash_ingest_then_posix_delete_clears_everything` | 反斜杠 ingest → 正斜杠 delete：`knowledge_docs.stored_path` 集合只有 `cfo/a.md`（无别名字符串）、文件已删、`_chunks()==[]`、`pending_deletions` 为空、墓碑 = `("cfo/a.md", 1)` |
| `test_dot_segment_ingest_does_not_duplicate_doc` | `./cfo//a.md` 复用同一 `doc_id`，不新建文档、不重嵌入 |
| `test_write_doc_backslash_then_delete_posix` | 写盘路径归一后意图表无残留、正斜杠删除生效 |

## 3. `purge_missing` 与彻底删除同等失效语义

每条被 purge 的路径，在**同一个写事务内**先推进代次，再删 chunks 与文档行：

```
INSERT INTO vault_path_state(stored_path,generation,updated_at) VALUES(?,1,?)
ON CONFLICT(stored_path) DO UPDATE SET generation=generation+1, updated_at=excluded.updated_at
→ DELETE knowledge_chunks WHERE doc_id=?
→ DELETE knowledge_docs WHERE id=?
```

**Event 交错回归** `test_inflight_ingest_after_purge_missing_cannot_resurrect`：
A 读完文件停在 TX1 之前（代次 0）→ 文件消失 → `mark_missing` → 保留期过 → `purge_missing(now=+retention+1d)` → 文件以**原样字节**重新出现（快照与 A 读到的一致，只有代次能拦）→ 放行 A。
断言：`_doc() is None`、旧 `doc_id` 的 chunks 为空、`vault_path_state.generation == 1`、A 返回 `stale`、`search(..., "boss") == []`；随后**新轮次** import 成功（`stale=False`、`reindexed=True`、新 doc_id），证明不是误伤。

## 4. `KnowledgeService.delete()` 服务层 boss 鉴权（fail closed）

**身份形态**：`delete(rel, *, identity=None)` 只接受 `identity_api` 签发、并经登记的 `Identity` **实例**；裸 `caller_role` 字符串、字典、任意伪造对象一律拒绝。

| 判定顺序（全部先于路径解析与磁盘动作） | 结果码 | 审计 |
|---|---|---|
| 未注入 `identity_api` | `identity_api_unavailable` | WARN `knowledge_delete_denied` |
| `identity is None` | `identity_required` | 同上 |
| `identity_api.authorize(identity)` 抛 `PermissionError`（未登记/撤销/过期/会话非 active/非 Identity 实例） | `identity_not_authorized` | 同上 |
| 登记角色 ≠ `boss` | `forbidden_role` | 同上（`actor_role` = 登记角色） |

工具层 `KnowledgeTool.delete_doc` 不再自行用 role 字符串放行：`_trusted_ctx is None` 仍先返回 `confirmation_required`（不动磁盘），否则把 `resolve_identity(...)` 得到的 `Identity` 实例下传服务层，审计角色取服务返回的**登记角色**。

**回归**（4 条新增）：

| 用例 | 断言 |
|---|---|
| `test_delete_without_identity_fails_closed` | 抛 `identity_required`；文件仍在、文档行仍在 |

## 9. 身份体系裁决（第四轮，只改语义，不改本轮代码）

**前提（已确认）**：v1 是**单机单用户工作台**。主对话窗口代表工作台所有者，不建设登录、密码、人脸或账号核验；不判断坐在电脑前的人是谁。

| 消息来源 | 系统认定身份 | 权限 |
|---|---|---|
| 主对话窗口提交（`source="main_chat"`） | `boss` | 老板权限 |
| 员工 Agent 自发协作消息（`source="agent_message"`） | 该 Agent 角色 | 按角色授权 |
| Agent 转述他人内容 | **保留发起者角色**（不提升） | 不因转述升级 |
| 正文自称 boss / 伪造角色标记 | **不采信** | 不提升 |

**对本轮代码的结论**：`Identity` 不删除，也不扩建；其定位由“人的身份凭证”正名为“**框架签发的消息来源凭证**”——能证明消息来自主窗口或某个 Agent，不能证明自然人身份。

- `KnowledgeService.delete()` 保持只允许 boss：凭证只能由入口铸造（minted `TrustedContext`），并查签发登记；裸 `"boss"` 字符串、字典、伪造对象一律 `identity_not_authorized`。
- 无可信来源继续 fail closed；拒绝先于路径解析与磁盘动作。
- watcher / reindex / UI 回填 / 直接调服务脚本均**不构成** boss 来源，只能用于导入与维护。
- **本轮不因该裁决改动任何源码**：已经推送的 `242f66e` 材料仍然是复审对象，避免 patch 漂移。正名留到 M5 消息信封落地时一并完成。

**M5 消息信封草案（供同轮审阅，未落代码）**：

```
{ "source": "main_chat" | "agent_message", "actor_role": "boss" | "sales" | ..., "message": "..." }
```
- `source` 与 `actor_role` 由调度层在消息进入时注入；模型输出、用户正文、转述文本不得覆盖。
- 转述一律按**发起者**角色处理（权限降级）；原始来源仅作审计字段 `origin_role`，不参与授权判定。
- `delete` 的入参届时由 `identity=` 正名为 `source_credential=`，服务层判定逻辑与 fail closed 语义不变，测试只换替身。
