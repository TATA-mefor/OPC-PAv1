## 四、B8 版本竞争保护（核心）

**协议**：读到正文 → 算 `source_hash` 并落库 → **事务外**做 embedding → 提交时
`UPDATE knowledge_docs SET indexed_hash=?,... WHERE id=? AND source_hash=?`；
`rowcount==0` 判定本轮过期 → **整事务回滚，一个 chunk 都不写**；`indexed_hash` 只在成功提交后前进。

**并发用例是真交错，不是顺序执行**：A 轮在独立线程中运行，嵌入替身进入时置 `Event`，主线程据此把文件改成 v2 并让 B 轮完整跑完，再放行 A。全程用 `Event` 编排，**不用 sleep 猜时序**。

**红证直接证明覆盖真实发生**（撤销条件更新后）：

```
>       assert contents == ["V2-NEW-CONTENT"]
E       AssertionError: assert ['V1-OLD-CONTENT'] == ['V2-NEW-CONTENT']
>       assert [c["content"] for c in _chunks(doc["id"])] == ["NEW-BODY"]
E       AssertionError: assert ['OLD-BODY'] == ['NEW-BODY']
```

即：无保护时旧任务确实把新版本的 chunk 正文覆盖了；有保护时落库内容为新版本且 A 轮返回 `stale=True`。
